# Turing Trainer

Интерактивный тренажёр по Машине Тьюринга для подготовки к заданию 12
КЕГЭ-2026 по информатике.

Приложение помогает перейти от чтения отдельной команды и пошаговой
трассировки к распознаванию циклов, поиску закономерностей и аналитическому
решению без полного прогона машины.

## Возможности

- разреженная бесконечная лента с отрицательными индексами;
- команды с направлениями `L`, `R`, `N` и `S`;
- ручные шаги, `undo`, `reset` и безопасный автозапуск;
- регулировка скорости автоматического выполнения;
- трёхфазная визуализация `write -> move -> state` для задач уровня 1;
- поддержка системной настройки `prefers-reduced-motion`;
- подсветка активных состояния, символа и команды;
- механика «Предскажи -> проверь»;
- три последовательные подсказки в учебном режиме;
- учебный и экзаменационный режимы;
- экзаменационный таймер;
- ответы типов `choice`, `prediction`, `steps`, `count` и `tape`;
- содержательный разбор ответа и диагностика ошибок;
- сохранение прогресса в `localStorage`;
- dashboard навыков, уровней, ошибок и рекомендаций;
- доступное модальное окно результата с focus trap;
- навигация состоянием приложения без React Router.

## Учебная траектория

```text
прочитать команду
  -> выполнить один шаг
  -> протрассировать короткий алгоритм
  -> понять цикл и роль состояния
  -> описать функцию машины
  -> найти закономерность
  -> решить без полной симуляции
  -> решить в экзаменационном режиме
```

Визуализация используется как временная опора. Цель тренажёра состоит не в
том, чтобы научить запускать симулятор, а в том, чтобы сформировать навык
самостоятельного анализа алгоритма.

## Контент

В проект входит набор из 12 авторских задач, включая экспериментальную пару А/Б.

| Уровень | Задач | Покрытие |
|:--|--:|:--|
| 1. Механика | 4 | чтение команды, один шаг, короткая трассировка, восстановление команды |
| 2. Алгоритм | 4 | цикл и роль состояния, несколько шагов, функция машины, обратное рассуждение |
| 3. Абстракция | 4 | закономерность, аналитическая экзаменационная задача и экспериментальная пара А/Б |

## Учебный комплект

Сценарий рассчитан на команды по 3–5 человек и два урока по 45 минут. Сначала используйте [комплект учителя](methodical-development/Teacher_methodical_kit.docx), затем раздайте [рабочий лист](methodical-development/Student_worksheet.docx), [проектное задание](methodical-development/Project_case_students.docx) и [шаблон маршрута](methodical-development/Diagnostic_route_template.docx). Для эксперимента применяются [карточки пары](methodical-development/Experiment_cards.docx), а при техническом сбое — [резервный комплект](methodical-development/Offline_reserve_pack.docx).

[Заполненный пример маршрута](methodical-development/Diagnostic_route_example.docx) предназначен для демонстрации после самостоятельной работы. Оценивание описано в [рубрикаторе](methodical-development/Detailed_product_rubric.docx), итоговая проверка — в [КИМах](methodical-development/Assessment_materials.docx). Актуальная презентация: [версия v3](methodical-development/Presentation_TuringTrainer_5_minutes_methodical_v3.pptx).

Каждая задача содержит конфигурацию машины, ответ, объяснение, три подсказки,
типичные ошибки и сведения об источнике. Данные проходят runtime-валидацию, а
эталонные результаты проверяются ядром в автоматических тестах.

## Быстрый старт

Для разработки рекомендуется Node.js 24 LTS. Минимальная версия определяется
актуальными требованиями Vite и Vitest; используемый lock-файл проверен с
Node.js 24.

```bash
git clone https://github.com/AlexeyDesyatnik/TuringTrainer.git
cd TuringTrainer
npm ci
npm run dev
```

После запуска откройте адрес, который покажет Vite, обычно:

```text
http://localhost:5173/
```

Для доступа к dev-серверу из Windows при запуске проекта в WSL можно
использовать:

```bash
npm run dev -- --host 0.0.0.0
```

## Структура проекта

```text
src/
  core/         чистое ядро Машины Тьюринга и проверка ответов
  types/        доменные типы машины, задач и прогресса
  data/         учебные задачи и runtime-валидация
  store/        Zustand-состояние сессии и прогресса
  components/   экраны и интерфейс тренажёра
  test/         общая настройка тестовой среды
```

Ядро не зависит от React и Zustand. Компоненты не изменяют внутреннее состояние
машины напрямую: все действия проходят через store сессии.

## Правила машины

Логический шаг всегда выполняется атомарно в следующем порядке:

1. Прочитать символ под головкой.
2. Найти команду для текущего состояния и символа.
3. Записать новый символ.
4. Переместить головку.
5. Перейти в новое состояние.
6. Увеличить счётчик команд.
7. Проверить остановку и лимит шагов.

Пустой символ хранится как `λ`, но не занимает место во внутреннем `Map`.
В интерфейсе он отображается как `␣`.

## Прогресс и приватность

Попытки сохраняются только в браузере пользователя под ключом:

```text
turing-trainer-progress
```

Сервер, база данных и авторизация не используются. В прогрессе хранятся режим,
правильность, длительность, подсказки, выполненные шаги, использование
симулятора и диагностированные ошибки.

Данные привязаны к браузеру и origin. Они не переносятся автоматически между
компьютерами или браузерами. На dashboard можно скачать прогресс в JSON и
восстановить его на другом компьютере. Импорт принимает только полностью
валидную резервную копию текущей версии и не стирает прогресс при ошибке.

## Production-сборка

```bash
npm run build
```

Готовые статические файлы появятся в каталоге `dist/`. Для локальной проверки
production-сборку следует открывать через HTTP-сервер, а не напрямую через
`file://`.

Проект не обращается к внешнему API и после загрузки статических ресурсов не
требует интернет-соединения.

Для запуска непосредственно с флешки без локального сервера используется
автономная сборка:

```bash
npm run build:standalone
```

Команда создаёт `dist-standalone/index.html` со встроенными JavaScript и CSS,
а также соседнюю папку `assets` с материалами занятия. Передавайте учителю весь
каталог `dist-standalone`, не меняя взаимное расположение файлов. `index.html`
можно открыть двойным щелчком через `file://`. Поскольку браузеры по-разному
привязывают `localStorage` к локальным файлам, для надёжного переноса прогресса
следует использовать экспорт и импорт JSON на dashboard.
