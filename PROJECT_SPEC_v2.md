## 1. ОПИСАНИЕ ПРОЕКТА

### 1.1. Что мы строим

Одностраничное веб-приложение (SPA) — интерактивный тренажёр для
подготовки к заданию 12 КЕГЭ по информатике 2026 года, посвящённому
анализу алгоритмов исполнителя «Машина Тьюринга».

Главная функция тренажёра — не просто визуализировать работу машины, а
**сформировать устойчивый способ решения задачи**: от понимания
отдельных команд к самостоятельному выявлению закономерности и решению
экзаменационной задачи без опоры на симулятор.

### 1.2. Целевая аудитория

- Ученики 11 класса, готовящиеся к КЕГЭ по информатике.
- Учителя информатики, использующие тренажёр индивидуально и для
  демонстрации на уроке.

### 1.3. Главная педагогическая цель

> **Сформировать у ученика устойчивый навык анализа работы Машины
> Тьюринга: от пошаговой трассировки отдельных команд к самостоятельному
> выявлению закономерности и решению задач экзаменационного типа без
> опоры на симулятор.**

Это главный критерий всех проектных решений.

### 1.4. Формируемые умения

1.  Читать команду по паре «состояние + символ».
2.  Правильно выполнять один шаг машины.
3.  Трассировать последовательность шагов.
4.  Распознавать роль состояний и повторяющиеся циклы.
5.  Описывать поведение машины на уровне алгоритма.
6.  Предсказывать результат без запуска машины.
7.  Находить закономерность и решать длинные задачи аналитически.
8.  Решать задачу экзаменационного типа в ограниченное время.

### 1.5. Ключевой принцип

> **Сначала визуализируй → затем управляй → затем предсказывай → затем
> объясняй → затем абстрагируй → затем решай без симулятора.**

Визуализация — временная опора, а не конечный способ решения.

### 1.6. Два режима

**Учебный режим:** подсказки, симулятор, шаг назад и повторные попытки
доступны; времени нет; ошибки используются для обучения.

**Экзаменационный режим:** таймер, без подсказок, разбор после ответа;
результат и время учитываются отдельно от учебных попыток.

### 1.7. Уровни обучения

| Уровень                     | Главный вопрос                               | Основное умение                                     |
|:----------------------------|:---------------------------------------------|:----------------------------------------------------|
| 1\. Понять механику         | «Как выполнить этот шаг?»                    | чтение команды и короткая трассировка               |
| 2\. Понять алгоритм         | «Что делает машина?»                         | циклы, состояния, предсказание                      |
| 3\. Абстрагировать и решить | «Как получить ответ без полной трассировки?» | закономерности, инварианты, длинные задачи, экзамен |

**Важно:** длина ленты и число состояний — лишь параметры сложности, а
не сама шкала сложности.

### 1.8. Целевые ориентиры

| Метрика                                                | Ориентир            |
|:-------------------------------------------------------|:--------------------|
| Короткая трассировка                                   | ≥95% после обучения |
| Предсказание одного/нескольких шагов                   | ≥90%                |
| Определение смысла простого цикла/состояния            | ≥80%                |
| Решение без подсказок                                  | ≥80%                |
| Среднее время экзаменационной задачи после закрепления | ≤6 минут            |

Это ориентиры эффективности тренажёра, а не обязательные индивидуальные
KPI.

### 1.9. MVP на одну неделю

**Обязательно:** корректное ядро, лента, таблица, шаг вперёд/назад,
режим «предскажи → проверь», 8–12 качественных задач, подсказки,
диагностика ошибок, разбор, сохранение прогресса.

**Можно отложить:** расширенный dashboard, сложные анимации, свободную
песочницу, расширенную геймификацию, 18+ задач, сложные мобильные жесты.

Лучше 10 методически проверенных задач, чем 18 задач сомнительного
качества.

## 2. КОНТЕКСТ ЗАДАНИЯ 12 КЕГЭ-2026

### 2.1. Общие сведения о задании

Задание 12 проверяет умение анализировать алгоритмы для исполнителя
«Машина Тьюринга». Задание имеет **повышенный уровень сложности**, время
выполнения — около **6 минут**. Средний процент выполнения по России:
25–35%.

### 2.2. Структура Машины Тьюринга

- **Бесконечная лента**, разделённая на ячейки (память). Индексация
  целыми числами (…, -2, -1, 0, 1, 2, …). Ячейки, в которые ничего не
  записано, содержат пустой символ.
- **Головка (каретка)** для чтения/записи символов. В каждый момент
  времени головка находится ровно над одной ячейкой.
- **Алфавит символов** A = {a₀, a₁, …, aₙ₋₁}, где a₀ — пустой символ λ
  (лямбда).
- **Множество состояний** Q = {q₀, q₁, …, qₙ₋₁}. Начальное состояние —
  q₀.
- **Таблица команд**: строки — состояния, столбцы — символы алфавита. На
  пересечении — команда.

### 2.3. Формат команды

Каждая команда состоит из **трёх элементов**:

1.  **Символ для записи** в текущую ячейку (может совпадать с
    существующим)
2.  **Направление движения**:
    - `L` (Left) — влево
    - `R` (Right) — вправо
    - `N` (None) — без сдвига
    - `S` (Stop) — остановка машины
3.  **Новое состояние** после выполнения команды

### 2.4. Порядок выполнения команды (КРИТИЧЕСКИ ВАЖНО!)

    ① ЗАПИСЬ: записать новый символ в текущую ячейку
    ② СДВИГ: сдвинуть головку в указанном направлении (если L/R)
    ③ СОСТОЯНИЕ: перейти в новое состояние
    ④ ПРОВЕРКА: если направление было S → остановка

**Сдвиг происходит ПОСЛЕ записи символа в текущую ячейку.** Это самая
частая ошибка учеников. Тренажёр должен визуализировать этот порядок
трёхфазной анимацией.

### 2.5. Остановка машины

Машина останавливается, если:

- Выполнена команда с направлением `S`.
- Для текущей пары (состояние, символ) **нет команды** в таблице.

### 2.6. Типичные ошибки учеников и их профилактика

| Ошибка                                             | Профилактика в тренажёре                           |
|:---------------------------------------------------|:---------------------------------------------------|
| Неправильный порядок: сдвиг до записи              | Трёхфазная анимация: ①запись → ②сдвиг → ③состояние |
| Путаница в направлениях L/R                        | Цветовое кодирование: L=синий, R=оранжевый         |
| Непонимание пустого символа λ                      | Визуальное обозначение «␣», серый фон пустых ячеек |
| Ошибки в подсчёте символов                         | Автоматический счётчик символов на ленте           |
| Неправильное определение начальной позиции головки | Явный маркер «Старт» + подпись состояния           |

### 2.7. Ментальная модель трассировки

Тренажёр целенаправленно формирует у ученика **внутренний алгоритм
трассировки**:

    ЦИКЛ трассировки (повторяется на каждом шаге):
      1. ПОСМОТРИ: какое состояние? какой символ под головкой?
      2. НАЙДИ: ячейку в таблице (строка=состояние, столбец=символ)
      3. ЗАПИШИ: новый символ в ячейку ленты
      4. СДВИНЬ: головку в указанном направлении
      5. ПЕРЕЙДИ: в новое состояние
      6. ПРОВЕРЬ: если S — стоп, иначе повторяй

## 3. МЕТОДИЧЕСКАЯ МОДЕЛЬ ОБУЧЕНИЯ

### 3.1. Траектория

``` text
ПОНЯТЬ
  ↓
СДЕЛАТЬ ВМЕСТЕ
  ↓
СДЕЛАТЬ САМОСТОЯТЕЛЬНО
  ↓
ПРЕДСКАЗАТЬ
  ↓
ОБЪЯСНИТЬ, ЧТО ДЕЛАЕТ МАШИНА
  ↓
НАЙТИ ЗАКОНОМЕРНОСТЬ
  ↓
РЕШИТЬ БЕЗ ПОЛНОЙ СИМУЛЯЦИИ
  ↓
РЕШИТЬ В ФОРМАТЕ КЕГЭ
  ↓
РЕШИТЬ НА ВРЕМЯ
```

### 3.2. Режим «Предскажи → проверь»

Перед выполнением шага ученик прогнозирует символ записи, направление и
новое состояние. Только затем тренажёр показывает фактический результат.

Для сложных задач можно спрашивать, что произойдёт через 3–5 шагов.

### 3.3. Режим «Что делает машина?»

После короткой трассировки ученик определяет функцию алгоритма, роль
состояний, условие завершения или закономерность.

### 3.4. Режим «Найди закономерность»

Короткий пример работы машины используется для вывода поведения на
длинной ленте. Цель — научить не трассировать сотни шагов механически.

### 3.5. Симулятор как временная опора

Симулятор не запрещается на сложных задачах. Тренажёр должен учить
выбирать стратегию: когда трассировать, а когда абстрагироваться.

Полезно фиксировать:

- решил без симуляции;
- использовал несколько шагов;
- полностью протрассировал;
- использовал подсказки.

### 3.6. Диагностика ошибок

**Операционные:** L/R, запись/сдвиг, λ, начальная позиция, неверная
клетка таблицы, подсчёт.

**Стратегические:** полная трассировка длинной ленты, пропущенный цикл,
непонятая роль состояния, нераспознанный однонаправленный проход,
подмена общего анализа перебором.

Стратегические ошибки особенно важны на уровнях 2–3.

### 3.7. Адаптивное повторение

``` text
ошибка
  ↓
диагностика
  ↓
короткое микро-упражнение
  ↓
новая задача на тот же навык
  ↓
проверка переноса
```

### 3.8. Критерий освоения

- **Пробовал** — была попытка.
- **Решает** — правильный ответ.
- **Самостоятельно** — правильный ответ без подсказок.
- **Освоено** — несколько успешных задач/аналогов на тот же навык без
  подсказок.

  **Zustand**

- ❌ Сторонние UI-библиотеки (MUI, AntD, Chakra) → кастомные компоненты
  на Tailwind
- ❌ Бэкенд, API, базы данных → только клиентское приложение
- ❌ `any` тип в TypeScript → строгая типизация
- ❌ Классовые компоненты React → только функциональные + хуки
- ❌ React Router → навигация через состояние в сторе
- ❌ Любые зависимости, не перечисленные в п.3.1

## 5. АРХИТЕКТУРА ПРИЛОЖЕНИЯ

### 5.1. Экраны приложения

Навигация реализована через состояние `screen` в сторе (без роутера):

    "home" → "selector" → "task" → [ResultModal поверх]
    "home" → "dashboard"

| Экран        | Компонент      | Описание                                               |
|:-------------|:---------------|:-------------------------------------------------------|
| Главный      | `HomeScreen`   | Кнопки: «Продолжить», «Выбрать задачу», «Прогресс»     |
| Выбор задачи | `TaskSelector` | Список задач по уровням, индикаторы решения            |
| Решение      | `TaskScreen`   | Условие + лента + таблица + панель + подсказки + ответ |
| Прогресс     | `Dashboard`    | Статистика по уровням, типам, ошибкам                  |

### 5.2. Ядро симулятора (`src/core/TuringMachine.ts`)

Чистый TypeScript-класс **без зависимостей от React**. Должен быть
полностью покрыт тестами.

**Публичный интерфейс:**

``` typescript
class TuringMachine {
  constructor(config: TuringMachineConfig)
  readSymbol(): Symbol
  step(): StepResult | null
  undo(): void
  reset(): void
  getTapeView(center: number, radius: number): TapeCellData[]
  countSymbol(sym: Symbol): number
  getState(): State
  getHeadPos(): number
  isHalted(): boolean
  getStepCount(): number
}
```

**Порядок выполнения в методе `step()`:**

1.  Прочитать символ под головкой
2.  Найти команду по ключу `${state},${symbol}`
3.  Если команды нет → `halted = true`, вернуть `null`
4.  Сохранить снапшот в `history` для `undo()`
5.  Записать `cmd.write` в текущую ячейку
6.  Сдвинуть головку (если `dir === 'L'` → head–, если `dir === 'R'` →
    head++)
7.  Изменить состояние на `cmd.nextState`
8.  Если `dir === 'S'` → `halted = true`
9.  Инкрементировать `stepCount`
10. Вернуть `StepResult`

**Лента реализована как `Map<number, string>`** — бесконечная в обе
стороны. Если ключа нет в Map — ячейка содержит `"λ"`.

### 5.5. Авто-режим выполнения

При `isAutoPlaying === true`:

- Интервал = `speed` мс из стора.

- **Обязательно** очищать interval при размонтировании компонента и при остановке.

## 7. КОНТЕНТ-ПЛАН И МАТРИЦА НАВЫКОВ

### 7.1. Принцип

Для MVP достаточно **8–12 полностью проверенных задач**. Количество
задач не является самоцелью.

Каждая задача обязана иметь:

- основной формируемый навык;
- уровень и обоснование уровня;
- тренировочный формат;
- проверенный ответ;
- объяснение;
- три методически разные подсказки;
- типичные операционные
и, где применимо, стратегические ошибки; - проверенную трассировку; -
аналог или микро-упражнение для переноса навыка, если это необходимо.

### 7.2. Матрица MVP

| №   | Уровень | Формат         | Навык                                        |
|:----|:--------|:---------------|:---------------------------------------------|
| 1   | 1       | микро-задача   | прочитать команду                            |
| 2   | 1       | предсказание   | выполнить один шаг                           |

| 6   | 2       | предсказание   | предсказать несколько шагов                  |
| 7   | 2       | объяснение     | определить функцию машины                    |
| 8   | 2       | обратная       | обратное рассуждение                         |

| 11  | 3       | экзамен        | комплексный анализ                           |

| Формат                 | Что тренирует                |
|:-----------------------|:-----------------------------|

### 7.4. Официальные материалы и аналоги

Официальное задание ФИПИ помечается как официальный материал и не
переписывается под видом авторского.

Авторская задача по мотивам оформляется как **«Авторская задача по
мотивам экзаменационного формата»**.

### 7.5. Валидация каждой задачи

``` text
☐ условие однозначно
☐ начальная лента и позиция головки проверены
☐ таблица команд проверена
☐ трассировка проверена
☐ ответ проверен независимо
☐ объяснение соответствует реальной работе машины
☐ подсказки ведут к следующему мыслительному шагу
☐ указан формируемый навык
☐ уровень обоснован
☐ типичные ошибки действительно возможны
☐ при необходимости есть аналог для переноса
```

### 7.6. Принцип переноса

После задачи на конкретный приём ученик должен встретить новую машину с
тем же приёмом, но другой таблицей, лентой или формулировкой. Цель —
перенос способа решения, а не запоминание конкретного примера.

## 8. СИСТЕМА ПОДСКАЗОК И ОБРАТНОЙ СВЯЗИ

### 8.1. Подсказки не штрафуют в учебном режиме

Использование подсказки не уменьшает учебный результат. Оно фиксируется
отдельно и влияет на статус самостоятельности.

В экзаменационном режиме подсказки недоступны.

### 8.2. Три уровня

| Уровень             | Функция                                             |
|:--------------------|:----------------------------------------------------|
| 1\. Вопрос          | активизировать нужное знание                        |
| 2\. Фокусировка     | направить внимание на конкретный механизм           |
| 3\. Частичная опора | снять конкретное затруднение, не выдавая весь ответ |

Подсказки должны быть различны по функции, а не просто перефразировать
решение.

### 8.3. Диагностическая обратная связь

После ошибки тренажёр по возможности определяет её тип и сообщает: 1.
что получилось; 2. где возникло затруднение; 3. что попробовать сделать
иначе.

### 8.4. Микро-упражнения

Повторяющаяся ошибка должна приводить к короткому упражнению на 10–20
секунд, а затем — к новой задаче на тот же навык.

### 8.5. Предсказание

Перед запуском шага:

``` text
Запишется: [   ]
Головка:   [ L / R / N ]
Состояние: [   ]
[Проверить прогноз]
```

## 10. СИСТЕМА ОЦЕНКИ, ПРОГРЕСС И ДИАГНОСТИКА

### 10.1. Учебный режим

Главный показатель — **самостоятельность**, а не балл.

| Статус         | Значение                                           |
|:---------------|:---------------------------------------------------|
| Пробовал       | была попытка                                       |
| Решает         | правильный ответ                                   |
| Самостоятельно | правильный ответ без подсказок                     |
| Освоено        | несколько успешных аналогичных задач без подсказок |

### 10.2. Экзаменационный режим

Отдельно учитываются:

- правильность;
- время;
- количество использованных шагов;
- использование симулятора.

Подсказки отсутствуют.

### 10.3. Диагностический профиль

Дашборд должен отвечать на вопрос: \> **«Что этому ученику нужно
тренировать дальше?»**

Пример:

``` text
Сильные стороны:
✓ выполнение отдельных команд
✓ короткая трассировка

Зоны роста:
⚠ роль состояний
⚠ поиск закономерности
⚠ решение длинных задач без полной трассировки

Рекомендация:
→ микро-упражнение на состояния
→ задача на закономерность
```

### 10.4. Данные попытки

``` typescript
interface AttemptStats {
  correct: boolean
  hintsUsed: number
  timeMs: number
  stepsExecuted: number
  usedFullSimulation: boolean
  errors: ErrorType[]
}
```

### 10.5. Повторение

``` text
ошибка → диагностика → микро-упражнение → аналогичная задача → проверка переноса
```

### 10.6. Не использовать как единственный показатель

Не считать главным показателем количество задач, время в приложении,
сумму баллов или число выполненных шагов.

## 11. ПРОЦЕСС РАЗРАБОТКИ С ПОМОЩЬЮ ИИ

### 11.1. Роль человека

Человек **НЕ пишет код**. Человек:

1.  **Формулирует промпты** (технические задания для ИИ)
2.  **Проверяет результат** (запускает, тестирует визуально)

4.  **Делает git-коммиты** после каждой успешной сессии
5.  **Принимает архитектурные решения** (зафиксированы в этом документе)

### 11.2. Правило атомарности

**Одна задача ИИ = один компонент / одна функция / один хук = не более
100 строк кода.**

Если задача больше — разбить на 2–3 промпта.

### 11.3. Структура рабочей сессии

    Сессия (40–60 минут):
      → Прочитать текущий код (5 мин)
      → Сформулировать промпт (10 мин)
      → Отправить ИИ, получить результат (15 мин)
      → Проверить, протестировать, закоммитить (20 мин)

### 11.4. Правило коммитов

**После каждой успешной сессии с ИИ — git commit.** Формат сообщений:

    feat: [описание нового функционала]
    fix: [описание исправленного бага]
    test: [описание добавленных тестов]
    style: [визуальные изменения без логики]
    refactor: [рефакторинг без изменения поведения]
    content: [добавление/изменение задач]
    docs: [документация]
    chore: [настройка проекта, деплой]

### 11.5. Правило «не верить ИИ на слово»

ИИ может сказать: «Готово, всё работает». **Это не значит, что всё
работает.**

Всегда проверяйте:

- `npm run build` проходит?
- `npm run test` — все тесты зелёные?
- Визуально в браузере — работает?
- `npx tsc --noEmit` — нет ошибок типов?

Если хотя бы один пункт не выполнен — возвращайте ИИ на исправление.

## 16. МЕТОДИЧЕСКИЕ РЕКОМЕНДАЦИИ

### 16.1. Для учеников: стратегия подготовки

**Неделя до КЕГЭ:** - **Дни 1–2:** Уровень 1, все задачи. Цель: довести
трассировку до автоматизма. - **Дни 3–4:** Уровень 2. Особое внимание —
типам «дополнение» и «обратная». - **День 5:** Задача-флагман
(демоверсия). Решить с симулятором, затем без. - **День 6:** Уровень 3,
оставшиеся задачи. Тренировка на время (таймер 6 мин). - **День 7:**
Повторение только тех задач, где были ошибки.

**На экзамене (алгоритм решения):** 1. Прочитать таблицу команд: машина
движется в одну сторону или возвращается? 2. Протрассировать 3–5 шагов
на черновике 3. Найти паттерн (что делает машина с каждым символом?) 4.
Применить паттерн ко всей ленте аналитически 5. Проверить ответ на
коротком примере
