# Руководство по учебному контенту

Документ предназначен для автора и проверяющего задач. Формат данных и
обязательный состав MVP определены в
[`PROJECT_SPEC_v2.md`](PROJECT_SPEC_v2.md).

## 1. Принцип набора задач

Для MVP нужны 8–12 полностью проверенных задач. Количество не является
самоцелью: десять методически выстроенных задач лучше восемнадцати задач с
сомнительными ответами.

Каждая задача имеет один основной навык и при необходимости дополнительные.
Уровень определяется требуемым способом рассуждения, а не только размером
машины.

## 2. Матрица покрытия

| Позиция | Уровень | Формат | Основной навык |
|:--|:--|:--|:--|
| 1 | 1 | `command-reading` | прочитать команду |
| 2 | 1 | `prediction` | выполнить один шаг |
| 3 | 1 | `trace` | выполнить короткую трассировку |
| 4 | 1 | `completion` | восстановить команду |
| 5 | 2 | `algorithm` | понять цикл или роль состояния |
| 6 | 2 | `prediction` | предсказать несколько шагов |
| 7 | 2 | `algorithm` | определить функцию машины |
| 8 | 2 | `reverse` | выполнить обратное рассуждение |
| 9 | 3 | `pattern` | перенести короткий пример на длинную ленту |
| 10 | 3 | `exam` | решить без полной трассировки |
| 11, если входит в набор | 3 | `exam` | комплексный анализ на время |
| 12, если входит в набор | 3 | `pattern` | перенести способ на новую машину |

Первые десять позиций образуют рекомендуемый базовый набор. Дополнительные
задачи усиливают проверку переноса.

## 3. Требования к задаче

У задачи должны быть:

- однозначное условие;
- уровень и объяснимое основание уровня;
- основной формируемый навык;
- формат из спецификации;
- полный валидный конфиг машины;
- проверенный ответ;
- объяснение способа решения;
- ровно три функционально разные подсказки;
- реалистичные типичные ошибки с диагностическими кодами;
- сведения об источнике;
- проверенная эталонная трассировка вне пользовательского текста задачи.

Для ответа `choice` все варианты должны быть правдоподобными, а неверные
варианты по возможности соответствовать известным ошибкам. Свободный текст не
используется для автоматической проверки в MVP.

## 4. Подсказки

Пример правильной последовательности:

1. «Какой символ сейчас находится под головкой?»
2. «Посмотри на пересечение строки q1 и столбца 0».
3. «Сначала запиши 1 в текущую ячейку, затем определи направление».

Плохая последовательность трижды сообщает один и тот же ответ разными
словами. Подсказка третьего уровня может дать часть операции, но не должна
выдавать итог всей задачи.

## 5. Объяснение результата

Объяснение должно раскрывать способ:

1. Какую команду или повторяющийся фрагмент нужно заметить.
2. Что этот фрагмент делает с лентой.
3. Почему машина останавливается.
4. Как получить ответ без лишней трассировки, если это задача уровня 2–3.

Простой список состояний без интерпретации недостаточен для задач на алгоритм
и закономерность.

## 6. Источники

Официальное задание помечается как официальный материал с точным названием и,
если возможно, ссылкой. Текст официального задания не выдаётся за авторский.

Изменённая таблица, лента или формулировка маркируется как «Авторская задача по
мотивам экзаменационного формата», даже если идея основана на демоверсии.

Перед публикацией необходимо проверить допустимость использования исходного
материала и корректность ссылки.

## 7. Независимая проверка

Авторская трассировка и проверка не должны быть одним и тем же действием.
Рекомендуемый процесс:

1. Автор создаёт конфиг, ответ, объяснение и контрольную трассировку.
2. Runtime-валидатор проверяет структуру данных.
3. Ядро выполняет машину до остановки или лимита.
4. Полученный результат автоматически сравнивается с ответом, где это
   применимо.
5. Человек независимо просматривает трассировку и объяснение.
6. Другой короткий пример проверяет перенос сформулированной закономерности.

ИИ не считается независимым подтверждением математической корректности без
проверки ядром и человеком.

## 8. Чек-лист задачи

- [ ] Цель сформулирована одним предложением.
- [ ] Указан основной навык.
- [ ] Уровень соответствует требуемому рассуждению.
- [ ] Условие однозначно.
- [ ] Алфавит содержит `λ` и все используемые символы.
- [ ] Начальное состояние и позиция головки валидны.
- [ ] Все команды ссылаются на существующие состояния и символы.
- [ ] Машина останавливается в пределах заданного лимита, если остановка
  ожидается условием.
- [ ] Эталонная трассировка проверена независимо.
- [ ] Ответ совпадает с результатом ядра.
- [ ] Объяснение раскрывает способ, а не только результат.
- [ ] Подсказки идут от вопроса к частичной опоре.
- [ ] Ошибки действительно возможны и имеют устойчивые коды.
- [ ] Источник указан корректно.
- [ ] Для навыка существует другая задача на перенос.

## 9. Контентные антипаттерны

- добавлять задачу без ручной проверки трассировки;
- доверять сгенерированной таблице без выполнения в ядре;
- создавать три перефразировки ответа вместо системы подсказок;
- смешивать несколько новых навыков в первой задаче уровня;
- использовать неоднозначный вопрос с несколькими правильными ответами;
- выдавать авторский аналог за официальное задание;
- менять ответ вручную, не обновляя контрольную трассировку и тест.
