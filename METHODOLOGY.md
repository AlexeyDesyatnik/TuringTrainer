# Методическая модель тренажёра

Документ объясняет педагогические решения проекта. Нормативные требования к
приложению находятся в [`PROJECT_SPEC_v2.md`](PROJECT_SPEC_v2.md).

## 1. Главная цель

Сформировать устойчивый навык анализа Машины Тьюринга: от чтения отдельной
команды и пошаговой трассировки до выявления закономерности и решения
экзаменационной задачи без опоры на симулятор.

Визуализация является временной опорой, а не конечным способом решения.

## 2. Формируемые умения

1. Читать команду по паре «состояние + символ».
2. Правильно выполнять один шаг.
3. Трассировать последовательность шагов.
4. Распознавать циклы и роли состояний.
5. Описывать функцию машины на уровне алгоритма.
6. Предсказывать результат до запуска.
7. Находить закономерность и инварианты.
8. Решать длинную задачу аналитически.
9. Решать экзаменационную задачу в ограниченное время.

## 3. Траектория обучения

```text
понять механику
  -> сделать вместе
  -> сделать самостоятельно
  -> предсказать
  -> объяснить алгоритм
  -> найти закономерность
  -> решить без полной симуляции
  -> решить в экзаменационном формате
  -> решить на время
```

Переход между этапами определяется не длиной ленты, а типом мыслительного
действия ученика.

## 4. Ментальная модель трассировки

На каждом шаге ученик повторяет внутренний алгоритм:

1. Определить текущее состояние и символ под головкой.
2. Найти соответствующую ячейку таблицы.
3. Определить записываемый символ.
4. Определить движение головки.
5. Определить новое состояние.
6. Проверить условие остановки.

Трёхфазная визуализация нужна прежде всего для закрепления порядка «запись →
движение → состояние». После освоения она сокращается, чтобы не замедлять
аналитическую работу.

## 5. Учебные механики

### 5.1. «Предскажи → проверь»

Ученик сначала прогнозирует результат команды, затем видит фактический шаг.
Это превращает просмотр анимации в активное воспроизведение алгоритма.

На следующем этапе прогноз может охватывать несколько шагов или итог короткой
трассировки.

### 5.2. «Что делает машина?»

После короткой трассировки ученик определяет функцию алгоритма, роль состояний
и условие завершения. Вопрос переводит внимание с отдельных команд на
структуру алгоритма.

### 5.3. «Найди закономерность»

Короткий пример используется для вывода поведения на длинной ленте. Ученик
должен сформулировать повторяющееся преобразование или инвариант, а не
протрассировать сотни шагов.

### 5.4. Симулятор как осознанный инструмент

Симулятор не запрещается на сложных задачах. Важно различать стратегии:

- решение без симуляции;
- несколько шагов для проверки гипотезы;
- полная трассировка короткого примера;
- избыточная полная трассировка длинной задачи.

## 6. Диагностика ошибок

### 6.1. Операционные ошибки

- перепутаны `L` и `R`;
- движение выполнено до записи;
- неверно понят символ `λ`;
- выбрана неправильная ячейка таблицы;
- неверно определена стартовая позиция;
- допущена ошибка при подсчёте.

### 6.2. Стратегические ошибки

- длинная лента полностью трассируется без необходимости;
- не замечен цикл;
- не понята роль состояния;
- не распознан однонаправленный проход;
- общий анализ заменён перебором частных случаев.

Обратная связь отвечает на три вопроса: что получилось, где возникло
затруднение и какое действие попробовать дальше.

## 7. Подсказки

Подсказка должна продвигать мысль, а не заменять решение:

1. Вопрос активирует нужное правило.
2. Фокусировка указывает на важный элемент машины.
3. Частичная опора снимает конкретное затруднение.

Три перефразировки ответа не считаются тремя подсказками. В учебном режиме
обращение за помощью не наказывается, но отделяет самостоятельное решение от
решения с поддержкой.

## 8. Адаптивное повторение

Желаемая последовательность после устойчивой ошибки:

```text
ошибка -> диагностика -> микро-упражнение -> новая задача на навык
       -> проверка переноса
```

Микро-упражнение занимает 10–20 секунд и тренирует одну операцию. Перенос
проверяется на другой машине, формулировке или начальной ленте.

## 9. Освоение

Одна правильная попытка означает, что ученик решил конкретную задачу, но не
доказывает освоение навыка. Для освоения нужны самостоятельные решения разных
задач на тот же навык.

Целевые ориентиры эффективности курса, не индивидуальные KPI:

| Умение | Ориентир после обучения |
|:--|:--|
| короткая трассировка | не менее 95% успешных попыток |
| предсказание шага | не менее 90% |
| понимание простого цикла или состояния | не менее 80% |
| решение без подсказок | не менее 80% |
| экзаменационная задача после закрепления | в среднем до 6 минут |

## 10. Педагогические антипаттерны

- делать симулятор главным способом решения всех задач;
- определять сложность только длиной ленты;
- выдавать полную трассировку вместо обучения закономерности;
- заменять понимание запоминанием таблицы;
- показывать правильный ответ без диагностики;
- считать количество выполненных задач достаточной оценкой обучения;
- искусственно скрывать полезный инструмент ради ощущения сложности;
- делать таймер центральным элементом учебного режима.
